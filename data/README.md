# data/

The single data root for the repository (`DATA_ROOT` in `studies/_paths.py`).
Nothing under `raw/` or `processed/` is committed, and `snapshots/` is ignored by
`.gitignore` (see "Committing a snapshot" below). Files are fetched from their
source or generated by scripts. `make check-data` prints the SHA-256 hash and row
count of the required inputs and verifies `snapshot_index.json`.

| Path | Contents |
|---|---|
| `raw/` | Files exactly as downloaded |
| `processed/` | Files derived from raw data (for example `aligned_planetary_data.csv`, read by `scripts/generate_artifacts.py`) |
| `snapshots/` | Frozen inputs of a published result, named `<name>_<sha12>.<ext>` with a `.manifest.json` next to each |
| `snapshot_index.json` | Committed list of every snapshot: file, SHA-256, rows, date range, source URL, licence, committable, committed |
| `registry/licences.yaml` | Per source: terms URL, licence, date read, decision (`commit` or `hash_only`) |
| `registry/mundane/` | Mundane event and chart registry files |

## Fetch scripts

`scripts/fetch/{fred,worldbank_pinksheet,cftc_cot,gfz_kp}.py` each download one
source, write `snapshots/<name>_<sha12>.<ext>` and its manifest, and add or
replace the entry in `snapshot_index.json`. The licence is read from
`registry/licences.yaml`; an unknown source is an error. `make check-data`
(or `python scripts/check_data.py --snapshots-only`) fails when a present file
does not match its indexed hash or a file in `snapshots/` is not listed.

## Committing a snapshot

A snapshot is committed only when its index entry has `committable: true`.
`.gitignore` currently ignores `data/snapshots/*`; committing an allowed file
needs an explicit exception there. For a `hash_only` source the file stays out
of git: the index carries its hash, and a reader checks their own download
against it. Entries with `committed: false` may be absent from a checkout.
